PKM System & Pedagogical Engine Architectural Specification

Version: 2.0.0-PROD | Target Repo: StudySpace-audit-pkm-plan

1. Executive Summary & Goals

Transform the legacy StudySpace into a personal knowledge management (PKM) engine capable of organizing topic-drifted conversations, dynamically invoking sub-tools, running diagnostic user assessments, rendering Gantt charts, and generating structured sub-agent files.

2. Architecture & Directory Topography

~/pkm/
├── main-skill.md                    # Root ontology, lazy-loading rules, and base capabilities
└── subjects/
    └── {subject_id}/
        └── {subcategory_id}/
            ├── agent.md             # Top-down compressed agent sub-file generated at runtime
            ├── telemetry.json       # Session metrics, drift logs, and latency stats
            └── sessions/
                └── {timestamp}.md   # Historical turn-by-turn context entries

Stub & Placeholder Syntax Protocol

All unwired runtime modules and placeholders generated by upstream agents MUST use this exact HTML comment syntax:

<!-- STUB: [Module_ID] | Schema: [Expected_Type] | Status: UNWIRED -->

3. Execution Phases & Rules

Phase 1: Initialization & Top-Down Compilation

  • Prompt the user to define explicit goals and desired session endpoints.
  • Compress root definitions from main-skill.md down into a lightweight sub-file at subjects/{subject_id}/{subcategory_id}/agent.md.

Phase 2: Baseline Skill Assessment

  • Search existing telemetry.json files for historical user performance.
  • If no history exists, issue a 3-question diagnostic assessment focusing purely on edge/friction points. Rule: Short answer questions only. No multiple choice.
  • Present baseline score and offer gap-calibration prompts to manually adjust difficulty.

Phase 3: Adaptive Teaching & Gantt Visualization

  • Query user on time constraints (Small / Medium / Large scoped sessions).
  • Render task breakdowns directly in markdown using Mermaid Gantt chart syntax:
```mermaid
gantt
    title Adaptive Learning Plan
    dateFormat YYYY-MM-DD
    section Friction Points
    Core Assessment :a1, 2026-08-20, 1d
    Targeted Remediation :a2, after a1, 2d
```

Phase 4: Telemetry, Reflection & Cleanup

  • Log drift instances, unresolved stubs, and call latencies into telemetry.json.
  • Prompt user upon session end (/end-session) with 2 micro-reflection questions on pace and explanation style.
